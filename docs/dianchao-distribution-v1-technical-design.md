# 电潮分销 V1 技术方案

状态：V1 第一阶段已完成；OAuth、签名、真实商品连接器、批量导入、MySQL迁移及首次真实商品调用均已验证
日期：2026-08-30

对应需求：[电潮分销 V1 产品需求文档](./dianchao-distribution-v1-prd.md)
接口依据：[1688 导入与微信小店铺货官方接口研究](./dianchao-distribution-api-research.md)

## 1. 技术目标

- 用最少的云资源完成可审核、可真实铺货的 V1。
- 保证“1688 账号、微信小店、商品、任务”之间的数据隔离。
- 批量任务在进程重启后仍能恢复，失败项可单独重试。
- 将 1688 和微信小店封装为独立连接器，后续增加云库或其他渠道时不重写核心业务。
- 所有正式 API 请求和业务数据处理在聚石塔环境内完成。

## 2. 推荐技术栈

| 层次 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript | 前后端共享类型，适合快速迭代及接口字段校验 |
| 前端 | React + Vite + Ant Design | 适合服务市场后台类页面，组件成熟、开发速度快 |
| 后端 | Fastify | 体积小、性能稳定、API 边界清晰 |
| 数据库 | 聚石塔 RDS MySQL 8 | 持久化租户、店铺、商品快照、任务和审计数据 |
| ORM/迁移 | Drizzle ORM | 无额外运行时二进制，类型和迁移文件清晰 |
| 参数校验 | Zod | API、环境变量和外部接口响应统一校验 |
| 测试 | Vitest + Playwright | 覆盖领域逻辑、连接器契约和关键网页流程 |
| 部署 | 单个 Docker 镜像，聚石塔原生 SAE | 本地、测试、正式环境使用同一构建产物 |

V1 暂不引入 Redis、消息队列、微服务注册中心和 Kubernetes 集群。

## 3. 应用结构

首版使用一个代码仓库、一个镜像和一个 SAE Web 应用。HTTP 服务和低并发任务执行器运行在同一进程内，但代码模块保持隔离。

```text
src/
  web/                 React 页面与前端状态
  api/                 HTTP 路由、鉴权、输入输出 DTO
  domain/              店铺、商品、铺货任务等领域规则
  connectors/
    alibaba1688/       1688 OAuth、签名、商品接口适配
    wechat-shop/       微信 Token、类目、素材、商品接口适配
  jobs/                MySQL 任务领取、执行、重试和状态机
  db/                  Schema、查询与迁移
  security/            密钥加密、脱敏、签名验证
  observability/       结构化日志、健康检查和审计
```

后续流量或任务量增加时，可使用相同镜像拆分成独立 Web 和 Worker SAE 应用，不改变领域及连接器代码。

## 4. 核心模块

### 4.1 1688 身份与租户

- 接收并验证 1688 授权回调。
- 将稳定的 1688 用户标识映射为内部 `tenant_id`。
- 校验用户订购/授权状态。
- 建立短期登录会话。
- 所有业务 API 从服务端会话取得 `tenant_id`，不接受前端任意传入租户 ID。

由于页面运行在 1688 容器内，需要在接口验证阶段确认第三方 Cookie 限制和 1688 推荐的会话传递方式。若浏览器限制嵌入页面 Cookie，则使用一次性授权码换取短期会话令牌，不把 1688 AccessToken 放进 URL。

### 4.2 微信小店连接器

- 保存并验证每个店铺的自研 AppID/AppSecret。
- 缓存和刷新店铺级 `access_token`。
- 统一处理微信错误码、限流和凭证失效。
- 封装类目、属性、素材、商品、SKU、库存和状态查询能力。
- 对上层返回内部统一模型，避免微信接口字段渗透到领域层。

### 4.3 1688 商品连接器

- 解析商品链接和 Offer ID。
- 获取商品、图片、详情、SKU、价格和库存快照。
- 提供基础搜索和推荐能力；没有获权时返回明确的“能力未开通”。
- 记录调用请求 ID、错误码和耗时，但不记录完整授权凭证。

### 4.4 商品转换

将 1688 商品快照转换为平台无关的内部商品草稿，再由微信连接器生成微信请求：

```text
1688OfferSnapshot
        ↓
DistributionDraft
        ↓
WeChatProductPayload
```

转换规则负责：

- 标题清理及长度校验；
- 图片格式和数量校验；
- 类目映射与用户确认；
- SKU 规格组合；
- 价格倍数及固定加价；
- 库存快照；
- 微信必填属性及资质检查。

### 4.5 批量任务

V1 使用 MySQL 任务表，不额外引入 Redis。提交一批商品时：

1. 创建 `distribution_batches`。
2. 根据“商品 × 店铺”生成 `distribution_jobs`。
3. 后台执行器按租约领取待处理任务。
4. 每完成一个阶段即持久化状态和外部 ID。
5. 进程重启后，超时租约可被重新领取。
6. 单项失败只影响自身，可按策略重试或人工重试。

必须为微信写入操作设置幂等保护。重试前先检查本地已保存的微信商品 ID 或查询外部状态，避免重复创建商品。

## 5. 数据模型

建议的最小数据表：

| 表 | 用途 |
|---|---|
| `tenants` | 1688 账号对应的租户 |
| `alibaba_authorizations` | 租户的 1688 用户标识、加密 Token、有效期和授权状态 |
| `tenant_sessions` | 短期登录会话，可定期清理 |
| `wechat_stores` | 微信小店、备注、加密凭证和绑定状态 |
| `wechat_tokens` | 加密 Token、过期时间和刷新锁 |
| `offer_snapshots` | 本次导入使用的 1688 商品快照 |
| `distribution_drafts` | 用户确认后的标题、类目、图片、SKU、价格和库存 |
| `distribution_batches` | 一次最多 20 个商品的批次 |
| `distribution_jobs` | 每个“商品 × 店铺”的独立任务和状态 |
| `distribution_job_events` | 任务阶段、外部错误码及重试记录 |
| `category_mappings` | 1688 类目到微信类目的候选映射 |
| `audit_logs` | 绑定、解绑、发布、重试等关键操作审计 |

所有租户业务表都包含 `tenant_id`。数据库唯一键、索引和查询函数同时约束租户边界。

## 6. 任务状态机

```text
QUEUED
  → FETCHING_SOURCE
  → VALIDATING
  → UPLOADING_MEDIA
  → CREATING_PRODUCT
  → SUBMITTED_FOR_REVIEW
  → REVIEWING
  → REVIEW_PASSED
  → LISTING
  → LISTED
```

任一步骤可进入 `FAILED_RETRYABLE`、`USER_ACTION_REQUIRED` 或 `FAILED_FINAL`。例如缺少类目权限、品牌或商品资质时进入 `USER_ACTION_REQUIRED`，不能盲目自动重试。用户手动重试时创建新的执行尝试，但保留原始事件记录。

批次最终状态：

- 全部成功：`SUCCESS`；
- 成功和失败并存：`PARTIAL_SUCCESS`；
- 全部失败：`FAILED`；
- 尚有任务执行：`RUNNING`。

测试和正式环境禁止共用数据库、密钥和微信店铺凭证。

## 8. 安全实现

- 使用 AES-256-GCM 加密微信 AppSecret 和持久化 Token。
- 主加密密钥通过 SAE 环境变量或密钥服务注入，不进入仓库。
- 使用结构化日志，并对 `secret`、`token`、`authorization` 等字段统一脱敏。
- 所有回调验证签名、时间窗口和重放标识。
- 敏感写操作校验 CSRF 或使用同源授权头。
- Session Cookie 必须设置 `Secure`、`HttpOnly`；嵌入场景按浏览器兼容性确定 `SameSite`。
- 店铺解绑后立即停止新任务；运行中的任务安全终止或标记失败。
- 限制单账号、单店铺和全局并发，避免打满 1688/微信接口额度。

## 9. 可观测性

## 11. 官方接口落地结论

### 11.1 1688

- V1 的核心导入接口为 `alibaba.fenxiao.productInfo.get`：用户输入商品链接或 Offer ID，解析出 `offerId` 后，用该租户的 1688 `access_token` 获取分销商品详情。
- 关键词搜索优先验证 `product.keywords.search`；搜索结果选中后仍回到 `productInfo.get` 获取完整详情。
- `alibaba.category.get` 和 `alibaba.category.attribute.get` 只提供 1688 类目与属性，不能直接当作微信类目与属性。
- 开放平台的应用详情与已购解决方案页面均确认当前 AppKey 为 `3255489`。方案 8.5 页面列出的接口仍需使用该应用的授权 Token 实际调用，才能确认 `alibaba.fenxiao.productInfo.get` 等核心权限与返回字段。
- “可选”证明接口已经分配到应用，但仍需用测试账号授权后的 Token 成功调用，才能确认授权、参数、返回字段和聚石塔网络全部正常。
- `productInfo.get` 调用失败会阻塞 V1；图搜、AI 选品不可用不阻塞按链接铺货。

### 11.2 微信小店

每个绑定店铺使用自己的自研 AppID/AppSecret，服务端调用稳定版 token 接口。单件商品的最小顺序为：

1. 获取或复用店铺级稳定版 `access_token`。
2. 获取类目树、叶子类目详情、本店类目权限和类目发布规则。
3. 调用 `channels/ec/product/categoryprecheck` 完成发品前校验。
4. 查询本店生效品牌，补齐必填属性、资质、运费及售后规则。
5. 使用 `shop/ec/basics/img/upload` 上传主图、详情图和必要资质图。
6. 调用 `channels/ec/product/add`，V1 使用 `listing=0`，持久化微信 `product_id`、`sku_id` 与内部 SKU 的映射。
7. 接收 `product_spu_audit` 审核事件，并使用 `channels/ec/product/get` 做补偿查询。
8. 审核通过后调用 `channels/ec/product/listing`，再次查询并以 `status=5` 作为已上架成功。
9. 商品创建后的库存写入使用 `channels/ec/product/stock/update`，不得把 1688 SKU ID 当作微信 SKU ID。

微信 `access_token` 当前有效期为 7200 秒。必须集中缓存并提前刷新；不可在每次业务请求中强制刷新，也不可把 AppSecret 或 Token 发送到浏览器。

### 11.3 聚石塔出网

- SAE 实例默认没有公网 IP，访问微信 API 需要为应用所在 VPC 配置公网 NAT 网关、SNAT 和固定 EIP。
- 公网负载均衡负责用户访问应用的入站流量，不能替代 NAT 的出站能力。
- 微信小店启用 IP 白名单后，将固定 NAT EIP 加入白名单；不要使用会随实例重建变化的单实例 EIP。

## 13. 尚需平台确认的审核风险

代发解决方案 8.5 版的官方概述同时包含商品铺货与订单自动回流。当前 V1 暂缓订单回流，可以用于快速开发和提审，但不能据此保证满足正式售卖审核。提交服务市场前应向 1688 审核人员确认；若被要求，再补最小订单回流闭环，不提前扩大本轮开发范围。
