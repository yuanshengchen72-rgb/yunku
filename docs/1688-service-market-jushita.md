# 电潮分销：1688服务市场发布与聚石塔关系

> 历史调研文档：项目现已更名为“电潮分销”，且 V1 已确定先实现“1688 商品批量铺货到微信小店”，不在首版建设 UnoPim 商品云库。当前确认范围见 [电潮分销 V1 产品需求文档](./dianchao-distribution-v1-prd.md)。

核对日期：2026-08-27

## 核心结论

1. 1688服务市场发布的对象是可订购的“软件或服务”及其服务 Offer，不是把安装包交给每个买家。对于网页版 SaaS，1688侧负责商品展示、订购、授权/交易和进入工具的入口，ISV负责实际网站和持续服务。1688多渠道分销协议明确写明，平台会在相关页面设置“进入您的工具”的超链接，ISV负责提供安全、稳定、合法的网站服务。[1688多渠道分销市场服务合作协议，第5.2、5.4条](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_b2b/suit_bu1_b2b202107201759_15509.html)
2. 没有在公开的1688通用协议中找到“所有类别必须把完整源码上传给服务市场”的统一要求。不过，应用正式上线需经过安全扫描，具体类目审核可能要求测试账号、产品说明、功能截图、资质或技术材料，最终以控制台字段和类目小二要求为准。[开放平台发布上线说明](https://developer.alibaba.com/docs/doc.htm.htm?articleId=103232&docType=1&treeId=1)
3. “开放平台应用上线”“服务市场上架”“聚石塔部署”是三件不同的事：前者解决 AppKey/API 正式调用，第二个解决对外销售订购，第三个解决程序运行和服务数据合规存储。
4. 对本项目风险最高的规则是：如果“电潮分销”按1688多渠道分销/代发工具接入，该专项合作协议明确要求把获得的所有服务数据存储在工具接入服务提供单位的聚石塔服务器。[1688多渠道分销市场服务合作协议，第5.4条](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_b2b/suit_bu1_b2b202107201759_15509.html)

## 三者的关系

| 层次 | 作用 | 本项目对应内容 |
|---|---|---|
| 1688开放平台应用 | AppKey/AppSecret、API权限、OAuth、调用额度、开发测试和正式上线 | 已订购“代发解决方案（服务商版）”的“电潮分销”应用 |
| 1688服务市场商品/Offer | 应用介绍、版本/套餐、价格、订购、退款/结算、市场入口 | 客户在1688找到并订购“电潮分销” |
| 电潮分销网页版 SaaS | 真正的商品云库、编辑、铺货、任务、订单等业务功能 | ISV开发和运营的网站 |
| 聚石塔 | 淘系电商应用的受控云运行与数据存储环境 | 部署网页后端、1688连接器、数据库及受控服务数据 |

1688平台应用市场协议把“应用”定义为ISV基于开放平台开发的“软件或服务”，并把应用市场定义为供ISV发布并进行自助交易的平台；用户正式获得使用许可前，ISV还应与用户签署相应的软件许可/服务协议。[1688平台应用市场入驻服务协议](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_b2b/suit_bu1_b2b201802011720_49107.html)、[阿里巴巴开放平台合作伙伴开发协议，第6.1—6.2条](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_b2b/suit_bu1_b2b202002111645_28701.html)

## 推荐的用户使用流程

1. 客户在1688服务市场浏览“电潮分销”服务 Offer。
2. 客户选择免费版或付费套餐并完成订购。
3. 客户点击1688提供的工具入口，进入电潮分销网页版。
4. 电潮分销校验客户订购资格，引导客户完成1688 OAuth授权。
5. 客户在网页版中选择/导入商品、编辑资料和铺货。
6. 应用按专项接口要求向1688回传铺货、同步及订单相关数据。

“超链接进入工具”来自1688多渠道分销专项协议第5.2条；订购与应用在线交易来自开放平台合作伙伴协议第6.1条。

## 是否需要完整软件才能上架

不是要求把路线图里的所有功能一次性做完，但正式上架时必须是可实际交付、与页面宣传一致的最小可售版本，而不能只有云库演示页面。

对于1688多渠道分销工具，公开专项协议要求的业务闭环包括：

- 把1688分销商品快速铺货到下游平台；
- 下游订单成立、退款或关闭后，按约定回流订单信息；
- 向1688提供真实的铺货、订单回流、货源更新同步等使用行为数据；
- 同时提供免费版与付费版，并限制免费版总铺货次数；
- 工具升级、改版时向1688同步相关文档并按规则审核。

依据：[1688多渠道分销市场服务合作协议，第3.3、3.4、5.3、5.5、5.6条](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_b2b/suit_bu1_b2b202107201759_15509.html)

因此，“只有商品云库和二次编辑”适合作为第一阶段内部 PoC，但很可能不足以作为该专项类目的最终服务市场版本。正式提审前至少应跑通一个下游渠道的铺货，以及订单/状态回流的最小闭环；具体最低渠道数和验收用例应向该解决方案的运营小二/钉群书面确认。

## 聚石塔是什么

聚石塔是淘宝开放平台与阿里云建设的受控电商云工作平台，提供运行应用所需的云资源及电商数据安全边界；它不是服务市场，也不是代码托管仓库。[聚石塔概述](https://developer.alibaba.com/docs/doc.htm?articleId=101130&docType=1&treeId=2)

淘系公开聚石塔规则列出的典型架构是：应用部署在ECS，数据库存放在RDS，API调用和涉及淘系数据的主要业务逻辑在塔内运行；商品管理、商品MDM、图片/视频工具和分销应用均列入必须入塔的应用标签。塔内数据与外部系统交互还受单独审核和准出规则约束。[聚石塔规则](https://developer.alibaba.com/docs/doc.htm?articleId=101896&docType=1&treeId=2)

该文档属于淘系通用/淘宝开放平台规则，不能单独替代1688专项认定；但本项目已有1688多渠道分销专项协议第5.4条的直接入塔数据要求，故应按“需要聚石塔”规划，除非1688运营小二对本 AppKey 书面确认了其他部署方案。

## 对 UnoPim 架构的影响

建议将正式架构调整为：

```text
1688服务市场（展示、订购、入口）
             │
             ▼
        电潮分销域名
             │
             ▼
聚石塔：Web/API + 1688 Connector + UnoPim
             │
       ┌─────┼─────┐
       ▼     ▼     ▼
   RDS MySQL Redis 受控对象/素材存储
             │
             ▼
    经批准的下游渠道接口
```

具体建议：

- UnoPim 3.0 支持 MySQL 8，优先选用聚石塔规则明确覆盖的 RDS MySQL，不优先采用 PostgreSQL。
- OAuth token、1688原始商品、客户编辑稿、SKU、图片引用、任务日志等都视为服务数据，默认留在塔内。
- 核心网页后端与1688 API调用代码部署在塔内；公开官网、帮助中心等不处理1688服务数据的内容可以独立评估。
- 不要在未审核前设计“塔内数据库实时复制到普通阿里云/其他云”的方案。
- 与抖音、拼多多、微信等下游平台的塔外数据交互必须在入塔架构审核时逐项说明场景和字段，确认可采用的出口方式。

## 正式提审前应向1688书面确认的问题

1. 当前 AppKey 和“代发解决方案（服务商版）”是否签署/适用《1688多渠道分销市场服务合作协议》。
2. 要求入塔的是全部系统，还是仅1688连接器、API调用、token和服务数据层。
3. 聚石塔可用的ECS、RDS MySQL、Redis、Elasticsearch及对象存储产品/版本范围。
4. UnoPim及自研SaaS使用Docker容器部署是否允许，安全扫描如何进行。
5. 对接抖音、拼多多等塔外平台时允许的网络出口、接口方式和字段清单审批流程。
6. 服务市场最小提审闭环：至少几个下游渠道、是否强制订单回流、免费版/付费版规则。
7. 审核时需要的测试账号、操作手册、软著、源码或代码扫描材料、隐私政策和用户协议清单。

## 明确、推断与待确认

- **官方明确**：服务市场可销售软件或服务；专项页面提供进入工具的超链接；ISV负责网站服务；多渠道分销协议要求所有服务数据存入聚石塔；专项业务包含下游铺货和订单回流。
- **基于官方条款的合理推断**：网页版SaaS无需把安装包交付给每个客户，服务市场是订购/入口层；核心系统应按入塔方式设计。
- **仍需平台确认**：是否必须上传完整源码、具体扫描方式、塔内允许的中间件、完整系统还是部分组件入塔、塔外渠道网络出口，以及当前类目的最小上架功能。

> 本文是技术与产品规划分析，不构成法律意见。1688协议和规则可变更，应保存当前 AppKey 所接受的协议版本，并取得运营小二/聚石塔架构审核团队的书面确认。
